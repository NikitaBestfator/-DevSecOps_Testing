## Найденные дефекты

Дефект 1 — R2: скидка 5% не применяется при subtotal = 5000
Нарушенное требование: R2
Входные данные: subtotal = 5000m, loyalty = false, express = false
Ожидаемый результат и расчёт: скидка 5% = 250; 5000 − 250 = 4750; доставка бесплатна (5000 ≥ 4000). Итог: 4750.
Фактический результат: 5000
Имя теста: SubtotalAt5000_Applies5PercentDiscount

Дефект 2 — R2: порог доставки считается, но скидка 5% не начисляется
Нарушенное требование: R2 (совместно с R4)
Входные данные: subtotal = 5000m, loyalty = false, express = false
Ожидаемый результат и расчёт: 5000 ≥ 4000 → доставка бесплатна; 5000 ≥ 5000 → скидка 5% = 250; 5000 − 250 = 4750.
Фактический результат: 5000
Имя теста: DeliveryThresholdUsesPreDiscountSubtotal

Дефект 3 — R3: при двух доступных скидках применяются обе, а не только большая
Нарушенное требование: R3
Входные данные: subtotal = 10000m, loyalty = true, express = false
Ожидаемый результат и расчёт: доступны 5% (по сумме) и 10% (по карте). По R3 применяется только большая — 10% = 1000; 10000 − 1000 = 9000; доставка бесплатна (10000 ≥ 4000). Итог: 9000.
Фактический результат: 8500 (обе скидки сложились: 10000 − 5% − 10% = 8550, затем округление вниз до 8500).
Имя теста: BothDiscountsAvailable_AppliesOnlyLarger10Percent

Дефект 4 — R5: экспресс-доставка не прибавляется к сумме после скидки
Нарушенное требование: R5
Входные данные: subtotal = 10000m, loyalty = false, express = true
Ожидаемый результат и расчёт: скидка 5% = 500; 10000 − 500 = 9500; экспресс-доставка 500 (R5); 9500 + 500 = 10000.
Фактический результат: 9500
Имя теста: ExpressAboveFreeThreshold_StillCosts500

Дефект 5 — R3 + R5: экспресс с картой — обе скидки и потеря доставки
Нарушенное требование: R3, R5
Входные данные: subtotal = 10000m, loyalty = true, express = true
Ожидаемый результат и расчёт: большая скидка — 10% = 1000; 10000 − 1000 = 9000; экспресс 500 (R5); 9000 + 500 = 9500.
Фактический результат: 8500 (применены обе скидки: 10000 − 5% − 10% = 8550 → 8500, экспресс не добавлен).
Имя теста: ExpressWithLoyaltyCard_Costs500AfterDiscount

Дефект 6 — R6: округление идёт не AwayFromZero, а вниз
Нарушенное требование: R6
Входные данные: subtotal = 1000.005m, loyalty = true, express = false
Ожидаемый результат и расчёт: скидка 10% = 100.0005; 1000.005 − 100.0005 = 900.0045; округление AwayFromZero до 2 знаков = 900.01; доставка 300 (1000.005 < 4000); 900.01 + 300 = 1200.01.
Фактический результат: 1200.00
Имя теста: FractionalSubtotal_RoundsAwayFromZero

Какие группы требований проверены?

Проверены все шесть требований контракта:
R1 — границы допустимого диапазона суммы: 0 и 100000 (проходят), -1 и 100001 (выбрасывают ArgumentOutOfRangeException).
R2 — порог скидки 5%: 4999.99 (скидки нет — верно), 5000 (скидка должна быть — дефект 1 и 2), 100000 (скидка есть — верно).
R3 — карта лояльности и выбор большей скидки: 1000 с картой (верно), 10000 с картой (должна быть только 10% — дефект 3).
R4 — порог бесплатной доставки 4000 и расчёт порога до скидки: 3999.99 (платная — верно), 4000 (бесплатная — верно), 5000 (бесплатная + скидка — дефект 2).
R5 — экспресс-доставка 500 руб. при разных суммах: 1000 (верно), 10000 (доставка не добавлена — дефект 4), 10000 с картой (дефект 5).
R6 — округление AwayFromZero: 1000.005 (округление вниз — дефект 6), 5000.005 (верно, так как дробная часть < 0.005).

Что осталось непроверенным?

Комбинация subtotal = 0 с картой лояльности (loyalty = true, express = false).
Комбинация subtotal = 0 с экспресс-доставкой (loyalty = false, express = true).
subtotal = 100000 с картой лояльности (там должна выбираться скидка 10%, а не 5%).
subtotal с отрицательным значением при loyalty = true (исключение должно выбрасываться до любых скидок).
Границы subtotal = 0 и subtotal = 100000 при express = true.

Почему упавшие тесты подтверждают нарушение требований, а не ошибку ваших ожиданий?

Потому что все ожидания рассчитаны вручную по тексту требований, а не получены вызовом тестируемого метода. 
Каждый тест проверяет одно правило из контракта, и расхождение факта с ожиданием означает, что реализация это правило нарушает.
Если бы ожидания были «подогнаны» под реализацию (например, взяты из фактического результата), 
тесты были бы зелёными, но не проверяли бы требования. 
Здесь же каждое ожидание можно пересчитать вручную и показать, что оно следует из R1–R6.
