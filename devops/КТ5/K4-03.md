# K4-03. Ansible и повторный запуск

## Выполненные команды

```bash
docker compose run --rm ansible demo.yml
docker compose run --rm ansible demo.yml
docker compose run --rm ansible banner.yml
docker compose run --rm ansible banner.yml

# 1. Inventory/localhost
## Объяснение: Ansible запускается внутри контейнера и управляет локальным хостом (connection: local),
## поэтому inventory состоит из одной строки localhost. SSH не нужен, так как мы не выходим за пределы контейнера.

# 2. Переменная и задача copy
## Объяснение: В плейбуке banner.yml я задал переменную workshop_message с моим кодом студента.
## Задача copy берет эту переменную и записывает её в файл /data/banner.txt с правами 0644 и владельцем 10001.
## Это гарантирует, что сервис, работающий под этим пользователем, сможет прочитать файл.

# 3. Идемпотентность (changed=0)
## Объяснение: При первом запуске demo.yml и banner.yml Ansible вносил изменения (changed=1 или больше).
## При повторном запуске Ansible проверяет текущее состояние системы и видит,
## что файлы уже созданы с нужным содержимым и правами. Поэтому он выводит changed=0 и ничего не меняет.

# 4. Проверка через API
## Объяснение: После запуска banner.yml я открыл http://localhost:8080/api/banner и увидел свой текст.
## После изменения переменной workshop_message и повторного запуска плейбука, API вернул новый текст.
## Это подтверждает, что Ansible обновляет данные корректно.

## Вопрос: Почему здесь не нужен SSH и что пришлось бы добавить для удалённого сервера?

## Ответ: В данном случае Ansible работает внутри контейнера и управляет самим собой (localhost),
## поэтому используется локальное подключение без сети. Если бы сервер был удаленным,
## пришлось бы добавить в inventory IP-адрес сервера, настроить SSH-ключи для беспарольного доступа
## и указать удаленного пользователя с правами sudo.
