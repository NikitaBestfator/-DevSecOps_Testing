#2. Проверка /health и /api/requests
## Объяснение: Проверка http://localhost:8080/health вернула 200 OK
## (в логах видно множество GET /health 200). Это liveness probe (проверка жизнеспособности).
## Она просто говорит: «процесс жив и отвечает на запросы».
## Если бы процесс завис, эта проверка упала бы, и Docker перезапустил бы контейнер.

## Объяснение: Проверка http://localhost:8080/api/requests вернула JSON со списком заявок.
## В логах видно GET /api/requests 200. Это readiness probe (проверка готовности).
## Она пытается выполнить реальную операцию (получить данные из базы). Если бы база данных упала,
## /health всё равно вернул бы 200, а /api/requests вернул бы ошибку 500 Internal Server Error.

## Вопрос: Какая проверка заметит отказ зависимости?

## Ответ: Проверка /api/requests (readiness probe). Она выполняет реальную операцию, зависящую от базы данных.
## Если зависимость (база) недоступна, эта проверка вернёт ошибку.
## Проверка /health (liveness probe) в этом случае продолжит возвращать 200 OK,
## потому что сам процесс API жив, он просто не может работать с данными.
