# K4-04. Учебный инцидент

## Выполненные команды

```bash
docker compose -f compose.student.yaml stop api
docker compose -f compose.student.yaml start api
docker compose -f compose.student.yaml logs --tail=20 web

# 1. Исходное состояние
## Объяснение: До начала эксперимента я создал тестовую заявку через браузер (http://localhost:8080).
## Приложение работало штатно, API отвечал на запросы, а Prometheus показывал статус UP для всех целей.

# 2. Сбой
## Объяснение: Я выполнил команду остановки контейнера api.
## При попытке открыть список заявок в браузере появилась ошибка 503 Service Unavailable.
## Это произошло потому, что web-сервер не смог перенаправить запрос на упавший api.

# 3. Сбор доказательств
## Объяснение: Через 10-15 секунд после падения я проверил метрики в Prometheus.
## Запрос up{job="workshop"} для api вернул 0 (сервис недоступен).
## Счётчик devops_http_requests_total{role="web",status="503"} начал расти, фиксируя ошибки на уровне web-сервера.
## В логах web появилась строка upstream_unavailable, подтверждающая, что web не может достучаться до api.

# 4. Восстановление
## Объяснение: Я выполнил команду запуска контейнера api. Через несколько секунд метрика up в Prometheus снова стала 1 (UP).
## Браузер снова начал отображать список заявок, старая заявка сохранилась (так как данные хранятся в базе), и я успешно создал новую.

# 5. Хронология
## Симптом: Ошибка 503 в браузере при попытке получить список заявок.
## Причина: Контейнер api остановлен, web не может достучаться до него.
## Действие: Перезапуск контейнера api.
## Проверка: Метрика up стала 1, список заявок загружается, данные сохранены.

# Вопрос: Это rollback версии или восстановление процесса?

# Ответ: Это восстановление процесса. Мы не откатывали версию кода на предыдущую (rollback),
## а просто перезапустили тот же самый контейнер (start api), который временно был остановлен. Данные при этом не пострадали.
